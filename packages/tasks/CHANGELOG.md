# @speekl/tasks

## 1.0.0

### Major Changes

- c803b06: Implemented the `.tasks` convention v2. A task is now a directory with a `task.md` manifest and a workspace (`state.md`, `design.md`, `plan.md`, `log.md`), nested at any depth; ids are paths and the `id` and `phase` fields are gone. The lifecycle is fixed (`BACKLOG`, `TODO`, `IN_PROGRESS`, `PAUSED`, `DONE`, `CANCELLED`) with a transition table, authorization, `--force`, and containment cascades; `state.md` is required to pause or hand off. Added priorities, assignees, finish gates (`finishes_after`), sessions with heartbeats and takeover of orphaned claims, `projects:` aliases with writes into listed trees, one lock per tree, `index.md` in place of `_index.md`, archive merge with `purge` and `delete`, and the commands `schedule`, `defer`, `pause`, `done`, `cancel`, `reopen`, `handoff`, `assign`, `unassign`, `priority`, `after`, `log`, `note`, `state`, `resume`, `mine`, `tree`, `archive`, `restore`, `purge`, `heartbeat`, `session-end`, `session-check`, `migrate` and `hooks install`. Removed `status` and the configurable statuses, roles and transitions. A v1 tree is refused by every command that opens it (`skill install` and `hooks install` only write beside it); `migrate` upgrades it once. The JSON shapes changed: task objects carry derived conditions, collections carry `scope`, `projects`, `malformed` and `unavailable`, and `move` reports the trees it skipped. `archive --resolved-before <when>` archives every resolved subtree older than a threshold in one call (`--all-resolved` every resolved subtree), skipping and listing the ones open tasks reference, and `archive_resolved_after_days` in `config.yml` makes `validate` report the ones still live that the command would take, naming apart the ones open tasks reference. A `task.md` a merge left with conflict markers is reported as malformed with the merge named, not as the YAML error the markers cause. `dep add` on a `CANCELLED` target says that the task is stranded; `purge` says which copy went and that a live task at the path stays; a takeover prints as one, not as `IN_PROGRESS → IN_PROGRESS`. `actors:` in `config.yml` lists who tasks may be assigned to, each with a line on who they are and a `type`, `person` or `agent` (a bare entry is a person, the name `agent` an agent, a mapping `codex: { type: agent, description: … }` says so itself; `tasks actors` reports it): a person's `pause` keeps the task for them (assignee set, `pause tom: IN_PROGRESS → PAUSED` in the log) while an agent's leaves it free, first in `ready`, and the output says which; `assign`, `handoff`, `new --assign` and `--as` then refuse other names, a write under the caller's own unlisted name is refused too (reads warn; `git config tasks.actor <name>`, read between `TASKS_ACTOR` and `user.name`, names a person once), `validate` warns `unknown-actor` for an open task whose assignee or claimant is unlisted, and `tasks actors` shows the roster with each actor's open tasks. An agent acts as `agent` by convention: the harness hooks export the name, and the skill sets it on every command without them, so a task assigned to `agent` reaches the agent either way. `init --actors [<names>]` writes the roster at once, and the scaffold's commented `actors:` example names the actor `init` resolved and `agent`. `docs:` in `config.yml` names where the project's documentation lives (name → path relative to the project root, a directory or a file, inside the repository or beside it): `resume` reports the locations with whether each exists here, `validate` warns `docs-missing` for an absent one, `init` scaffolds a commented example, and the agent protocol and the skill have an agent bring the listed documentation that describes what the task changed up to date before `done`, within the task's scope, saying so in the message; and have an agent name every commit made for a task in its log before the work ends, by hash and branch, with the task's id in the commit message where the project's commit convention allows it; the protocol's entry rules now say what comes first (this session's claims, then the highest priority among own orphans and the inbox, then new work), that an own orphan is claimed before it is read, that a turn is not a session, that unavailable listed projects are a person's to fix, and that an agent without the hooks heartbeats through a quiet stretch. `list` and `tree` take `--depth <n>` to show the tasks at most _n_ levels of containment deep, counted from the scope, and `--top` for the top level alone: the epics and the tasks that stand on their own; `list --active` selects the tasks with a claimed task beneath them; and overviews show the effective priority in a column of its own instead of among the labels. A `--json` answer longer than the pipe's buffer now reaches the reader whole: the process exits once its output is flushed, where it exited at once and cut the answer at 64 KiB with exit code 0. Commands that stayed changed meaning or shape: `new <path> <title…>` replaces `new <phase> <name> [--id]`; `move <source> <destination>` replaces `move <id> <phase>`; `--phase` and `--status` on `list` and `ready` gave way to `--scope`, `--all`, `--local` and the `--<situation>` filters (a scope, given or configured, keeps an overview and `claim --next` to the local tree; the listed projects are spanned only without one, and the footer says how many rows they contributed); the log is history, not a channel: `note <task> "<text>"` appends a dated, attributed input for whoever works next under `## Notes` of `task.md` and logs it, and the protocol no longer calls the last log entry the note for the next reader; `log <task>` without text prints a task's history, and `--archived` on `show`, `log <task>` and `log --since` reads the archive without restoring anything; `claim --as` became the global `--as`, beside the new globals `-C` and `--session` (without `-C`, a command run inside a linked git worktree discovers the tree at the same place in the main checkout, so hooks and commands reach the live tree and not the snapshot committed on the worktree's branch); `delete` no longer archives and lost `--purge`: it removes a never-worked task only; `release` is refused once a `state.md` exists; `validate --fix` repairs only `index.md`.

## 0.1.0

Initial release.

### Added

- `tasks init` — scaffold `.tasks/` with config, README, and gitignore, and
  install the agent skill (`--no-skill` opts out).
- `tasks new` / `show` / `list` / `ready` — create and read tasks.
- `tasks claim` / `release` / `status` — task ownership and lifecycle.
- `tasks dep add|rm|list` — dependency management with cycle detection.
- `tasks move` / `delete` — relocate a task's phase, archive or purge.
- `tasks reindex` / `validate` — regenerate `_index.md`, check tree integrity.
  `validate` warns when a committed `_index.md` no longer matches the tasks on
  disk, and `--fix` regenerates it; it stays a warning, because the index is not
  a source of truth and CI should not fail on it.
- `tasks skill install [--force]` — install the bundled agent skill into
  `.claude/skills/tasks/`, so agents discover the convention on their own.
- `--json` on every command, with meaningful exit codes (0 ok, 2 usage,
  3 not found, 4 conflict).

Requires Node 20 or newer.
